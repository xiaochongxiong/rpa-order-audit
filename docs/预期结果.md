## 一、审核三态规则（D2 实现）

优先级：**自动拦截 > 转人工 > 自动通过**（一单命中多条时取最高优先级）。

### 自动拦截（硬违规，命中任一）
| 编号 | 规则 |
|---|---|
| R1 | 实付金额 = 0 且 付款状态 = 已支付（金额与状态矛盾） |
| R2 | 实付金额 < 成本 × 数量（低于成本价卖出） |
| R3 | 数量 > 可用库存（超卖） |

### 转人工（软异常，命中任一）
| 编号 | 规则 |
|---|---|
| M1 | 手机号不是 11 位纯数字 |
| M2 | 省 / 市 / 区 / 详细地址任一为空 |
| M3 | 备注含「转寄 / 代收 / 自提」任一关键词 |
| M4 | 历史退货次数 ≥ 3 |

### 自动通过
以上都不命中。

## 三、对账规则（D3 实现）

应结金额 = 实付金额 − 平台扣点 − 退款 + 补差
判定：账单金额 == 应结金额 → 平；否则 → 差异，并标出类型。

| 类型 | 判定条件 | 埋点单号 |
|---|---|---|
| 金额不符 | 两边都有该订单号，但账单金额 ≠ 应结金额 | O002（少 5 元） |
| 账单缺单 | 订单表有、账单表无 | O011 |
| 订单缺单 | 账单表有、订单表无 | O999 |

其余 **14** 单对账为「平」（2026-11-22 实测修正：订单号并集为 17 个＝订单表 16 单 + 账单表独有的 O999，扣除 3 个差异单后剩 14 单；原写 13 单是按订单表 16 单误算）。

## 四、说明（两处刻意简化）
1. 对账按订单号全量匹配，未区分"只有审核通过单才对账"——真业务会先过滤，这里为突出匹配逻辑本身。
2. 扣点统一按实付 5% 模拟，退款/补差多为 0——真实账单规则更复杂，模拟数据只求规则可复现。
