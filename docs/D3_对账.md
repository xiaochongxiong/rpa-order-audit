# D3 · 平台账单对账（差异追到订单级）

> 目标：把审核单（`模拟订单.xlsx`）与平台账单（`平台账单.xlsx`）按订单号匹配，找出三类差异并追到订单级，输出 `对账结果.xlsx`。
> 前置：D2 已完成（三态分流）。D3 是项目三的第二个卖点——证明"对账能定位到具体哪一单差多少"。
> 标准答案：`docs/预期结果.md` 第三节。

## 一、今天要理解的三件事

### 1. 对账口径（业务本身，必须懂）

```
应结金额 = 实付金额 − 平台扣点 − 退款 + 补差
对账结论：账单金额 == 应结金额 → 平；否则 → 差异，标出类型与差额
```

含义：平台从货款里扣走手续费（扣点）、可能退过款、也可能补过差价，所以商家实际该收到的钱不等于买家付的钱。对账就是核对"平台结算给我的钱"是否等于"按规则算出我该收到的钱"。

### 2. 三类差异（这是 D3 的核心价值）

| 类型 | 判定条件 | 埋点单 | 业务含义 |
|---|---|---|---|
| **金额不符** | 两边都有该订单号，但账单金额 ≠ 应结金额 | O002（少 5 元） | 平台多扣/少结，要找平台核 |
| **账单缺单** | 订单表有、账单表无 | O011 | 卖出去了但平台没结算，要催结算 |
| **订单缺单** | 账单表有、订单表无 | O999 | 账单出现陌生订单，要查是否漏记/串号 |

**为什么"追到订单级"重要**：只报"这个月差 5 元"没有可操作性；报"O002 差 5 元、平台扣点异常"，人才能拿单号去找平台。这就是 RPA 对账比人工 Excel 核对强的地方——**自动定位到行**。

### 3. 实现方式：沿用 D2 验证过的自包含方案

D2 已证明：你的影刀版本只有「插入代码段(Python)」可用，且变量映射不可靠。D3 **完全沿用同一模式**——代码自己读两张 Excel、自己算、自己写结果，贴一条指令即可。

## 二、影刀操作步骤（1 条核心指令）

1. 新建 PC 自动化应用 → 自定义搭建（同 D1/D2）
2. 拖一条「**插入代码段(Python)**」
3. 打开，把 `docs/D3_自包含代码.py` 的**全部内容**复制粘贴到代码区
4. 确定 → 运行

代码要点：
- `read_table()` 把 Excel 读成字典列表，按订单号建索引（`order_map` / `bill_map`）
- `all_ids = 订单号并集`——**关键**：用并集而非订单表，才能发现"账单表独有的 O999"
- `money()` 统一保留 2 位小数，避免浮点比较误差（如 188.10000001 ≠ 188.1）
- 输出 8 列：订单号 / 平台 / 实付金额 / 账单金额 / 应结金额 / 对账结果 / 差额 / 说明

> 我已在本机用真实数据实测：18 行（1 表头 + 17 订单号）、8 列、**平 14 / 金额不符 1 / 账单缺单 1 / 订单缺单 1**，三类差异单号与 `预期结果.md` 完全一致。

## 五、卡住了自查

| 现象 | 先看这里 |
|---|---|
| 报 `ModuleNotFoundError` | 代码自动 pip 装；失败则影刀菜单 → Python → pip 装 openpyxl |
| 报 `FileNotFoundError` | 检查 `ORDER_FILE` / `BILL_FILE` 两行路径 |
| O999 没被找出来 | `all_ids` 必须是两表订单号的**并集**，不能只遍历订单表 |
| 金额全判"不符" | 检查扣点是否重复扣（账单里的扣点已是金额，不要再乘 5%） |
| 差额出现一长串小数 | `money()` 是否生效，金额要 round 到 2 位 |
